## Purpose
Accept a user-supplied URL safely. This is the security boundary of the whole product: every
byte analysed downstream enters here.

## Scope — in
- Normalisation: scheme, lowercase host, punycode/IDN, strip fragment, preserve meaningful query, resolve relative input.
- **SSRF guards:**
  - `http`/`https` only — reject `file:`, `data:`, `gopher:`, `ftp:`, everything else.
  - Reject IP literals (v4, v6, and encoded forms: decimal, octal, hex, IPv6-mapped).
  - Reject private, loopback, link-local, and reserved hostnames, including `localhost`, `*.local`, `*.internal`, and `169.254.0.0/16`.
  - Follow redirects **manually** with `redirect: 'manual'`, re-validating every hop. Max 5 hops.
- Response guards: `Content-Type` must be HTML; body capped (default 2 MB); request timeout; reject non-2xx with a clear reason.
- `robots.txt` fetch and parse; honour disallow for our user-agent.
- Identifying user-agent containing the project URL.

## Scope — out
No crawling or link discovery — module 1 is single-page. No rate limiting across requests
(no shared state on free tier; revisit if a public demo is ever hosted).

## Files owned
`src/intake/**`

## Contracts produced
- `IntakeResult` = `{ finalUrl, status, contentType, html, bytes, redirectChain, robotsAllowed }`

## Acceptance criteria
- An adversarial hostname corpus (committed as a fixture) is rejected in full. Include at minimum: `127.0.0.1`, `0x7f.1`, `2130706433`, `[::1]`, `localhost.`, `foo.internal`, `169.254.169.254`, `http://evil.com@127.0.0.1`, and a public host that 302-redirects to a private one.
- A redirect chain ending at a private address is rejected **at the hop**, not after fetching.
- Oversized and non-HTML responses are rejected without buffering the whole body.
- `robots.txt` disallow is honoured and surfaced as a reason, not a generic failure.

## Validation
```
npm test -- intake
```
Every adversarial fixture must be rejected. A single miss fails the task.

## Handoff notes
**Built.** Normalisation, SSRF guards, manual redirect following with per-hop
re-validation, streamed body cap, robots.txt.

- `MAX_PAGE_BYTES` lowered 2 MB → **500 KB**: extraction measures ~0.02 ms/KB against a 10 ms CPU limit, so 2 MB would fail with error 1101.
- robots.txt is cached through the Workers Cache API. Without it, every page of a site scan re-fetched it.
- **Not done:** the adversarial hostname corpus from the acceptance criteria. The guards are written and unit-reachable but not yet exercised by a committed fixture list. **This is the biggest untested surface in the codebase.**


**Update:** adversarial corpus now built — `test/fixtures/ssrf-hosts.ts`, 36 URLs that must be rejected (loopback in 6 encodings, RFC1918, CGNAT, IPv6 link-local and unique-local, cloud metadata, internal TLDs, credential-disguised authorities, 5 non-HTTP schemes) plus 8 public URLs that must be accepted so the guard is not simply over-broad. All 47 pass.
