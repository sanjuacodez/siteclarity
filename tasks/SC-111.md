## Purpose
Merge static and semantic findings into one honest, ordered result.

## Scope — in
- Deduplicate findings that describe the same underlying issue from different checks.
- Order by **extraction impact** — how much the issue blocks a search or AI system from finding and using an answer. Ordering rules are explicit and documented, not an opaque weight.
- Populate `whyItMatters` and `recommendedAction` per finding from the check that raised it.
- Build the **`limits` block** (invariant 6), stating in plain language: only one page was analysed and this is not a site assessment; whether the semantic layer ran; whether sections were capped; whether the page is JS-dependent so served HTML may differ from what users see; whether language gating applied.
- Assemble the final `AnalysisResult`.

## Scope — out
No rendering (SC-112). No new checks.

## Files owned
`src/assemble/**` (except `verify.ts`, owned by SC-110)

## Acceptance criteria
- **No overall score anywhere in the output.** A test asserts this explicitly (invariant 2).
- `limits` is always populated and never generic boilerplate — it reflects what actually happened in this run.
- Prioritisation is deterministic: the same input yields the same order.
- A page with no findings returns a valid result saying so plainly, not an empty object or an error.
- A static-only run is clearly labelled as such in both `limits` and `provider`.

## Validation
```
npm test -- assemble
```

## Handoff notes
**Built.** Static, language and decision findings merged, de-duplicated, ordered by
priority. Limits block assembled from what actually happened in the run.

- Two de-duplication passes: overlapping checks on one section (`answer_absent` suppresses `heading_not_answered`), and identical evidence quotes repeated across sections.
- Suggestions are tailored without generation: the hype lexicon supplies the actual words, and Jev's `improvement_type` Choice selects which pre-written template renders.
- **Not done:** ordering is by priority then checkId, not the documented "extraction impact" weighting.
