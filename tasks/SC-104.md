## Purpose
Turn HTML into an addressable document model. **Passage IDs are the backbone of the entire
evidence system** — every finding in every future module points at one.

## Scope — in
- `HTMLRewriter` streaming parse. **No DOM library** (see `AGENTS.md` §7).
- Document metadata: `<title>`, meta description, `lang`, canonical, meta robots, Open Graph.
- Heading tree (h1–h6) preserving order and depth.
- **Sections**: a heading plus all content up to the next heading of equal or higher level.
- **Passages**: paragraphs, list items, table cells, definition entries within a section.
- **Stable passage IDs**: deterministic and re-run-stable. Recommended `s{n}:p{m}:{hash8}` where the hash is over normalised passage text, so an ID both locates *and* verifies content.
- Raw JSON-LD blocks captured verbatim (parsed in SC-106, not here).
- Link inventory (internal/external) — captured now, unused until module 4.
- JS-dependency signal: ratio of rendered text to script bytes, empty SPA root detection, `<noscript>` presence.

## Scope — out
No interpretation. No scoring. No schema validation (SC-106). No language analysis (SC-107).
This task produces structure only.

## Files owned
`src/extract/**`

## Contracts produced
- `ExtractedDoc` = `{ meta, headings[], sections[], passages[], jsonLdRaw[], links[], jsDependency }`
- `Passage` = `{ id, sectionId, kind, text, charStart, charEnd }`

**This is the most-depended-upon contract in module 1. Get it right; changing it later is expensive.**

## Acceptance criteria
- Parsing the same HTML twice yields byte-identical passage IDs.
- A cosmetic edit elsewhere in the document does not change unrelated passage IDs.
- Every `passage.text` is recoverable verbatim by ID — this is what SC-110 verifies against.
- Malformed HTML (unclosed tags, nested `<p>`, stray `</div>`) does not throw.
- Extraction of the largest fixture stays within the CPU budget (SC-114).
- A JS-rendered SPA shell is correctly flagged as JS-dependent.

## Validation
```
npm test -- extract
```
Include an idempotency test (parse twice, compare IDs) and a malformed-HTML corpus.

## Handoff notes
**Built.** `HTMLRewriter` streaming extraction, stable `s{n}:p{m}:{hash8}` passage IDs
(FNV-1a), idempotency verified by test.

- **Page chrome suppression was the single highest-impact fix.** `nav`, `footer`, `aside` and `body > header` are skipped. Before this, a footer with no headings was absorbed into whatever the last heading happened to be — one page gave a "related post" heading 22 passages of nav links and phone numbers, which the model judged as a section promising nothing.
- Use `body > header`, never bare `header`: article titles live in `<header><h1>` and suppressing all headers produced false "no H1" findings.
- **Boilerplate rule:** text under **two or more different headings**. Counting occurrences alone is wrong — a word can legitimately repeat inside one section; crossing section boundaries is the signal.
- HTML entities are decoded. Not cosmetic — a quote must match what a reader sees or SC-110 is meaningless.
- Measured: 297 KB → 6 ms median, 855 KB → 9 ms median / 11 ms p90.
