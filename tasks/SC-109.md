## Purpose
Build **states**, author **typed questions**, and turn returned decisions into findings.

## The core design: scope-partitioned state, not chunked pages

Jev 1.13 has a 32k context. The instinct is to chunk a long page across calls. **Don't.**
Chunking is fragile, loses context at boundaries, and does not scale to the multi-page
modules at all.

The better answer: **almost every question in SiteClarity is section- or passage-scoped, not
page-scoped.** Give each question exactly the state it needs and nothing else.

| Scope | State contents | Typical size | Questions |
| --- | --- | --- | --- |
| **Page** | title, meta, heading tree, section index, first section | 2–4k tokens | entity clarity, page purpose, overall structure |
| **Section** | one section's passages + its heading + a one-line page anchor | 200–800 tokens | answers-its-heading, self-contained, extraction-readiness |
| **Passage** | one claim passage + its section heading | ~100 tokens | checkable claim, specificity, promotional intensity |

Each state is small and **always fits**. Truncation never happens, so it never has to be
disclosed or apologised for.

This is not merely a workaround — it is **more correct**. "Is this section understandable in
isolation?" is a question about the section *alone*; feeding the model the surrounding page
actively corrupts the answer. Narrower state also removes distractor text, which generally
improves decision accuracy.

### Cost of many small calls

A 30-section page becomes ~31 calls instead of 1. This is fine:
- Issued concurrently, ~0.4–1 s wall clock (Jev is ~0.4 s per call).
- Network wait, so ~0 CPU against the 10 ms budget.
- ~$0.0004 per case; a page costs roughly a cent at list price.
- Well under the 1,000 Cloudflare-services subrequest limit. **Confirm** whether `AI` binding calls count as external (limit 50) — SC-108 measures this. If they do count as external, group sections into batched states under a token budget rather than abandoning the design.

**Supersedes the earlier "one call per page" rule**, which was wrong: it optimised for call
count at the expense of both correctness and scalability.

## How this scales to the other nine modules

The same principle, stated generally: **decisions are local; aggregation is deterministic
code.**

- Per-page decisions run against page-scope states — never "100 pages in one state".
- Roll-ups (counting, comparing, ranking) happen in TypeScript, not in the model.
- Genuinely cross-page questions use a **compact summary state**: one line per page (URL, title, detected offering, stage). 100 pages ≈ 5k tokens, comfortably inside 32k.

This is what makes a 500-page site audit reachable from a 32k-context model.

## Scope — in
- State builders for all three scopes, from `ExtractedDoc`. **Never raw HTML.**
- Versioned question catalogue (data, not inline code) — see `DECISIONS.md` for the module-1 question table.
- **Token budgeter**: measure every state before sending; assert it fits with headroom. If a single section somehow exceeds budget, split by passage — deterministically, and disclosed in `limits`.
- Concurrency control: bounded parallelism, with a configurable ceiling.
- **Confidence thresholding**: `confidence` below a documented named threshold → `cannot_assess`. Never a guess. Tune against SC-113's corpus.
- **Degradation**: no backend → complete static-only result, clearly labelled.

## Scope — out
No structural checks (SC-106). No quote resolution (SC-110). No prose generation — copy is
templated in SC-111.

## Files owned
`src/semantic/**`, `src/semantic/state/**`, `src/semantic/questions/**`

## Prompt injection
Jev returns only schema-defined values, so a page cannot induce prose or a fabricated quote.
Residual risk is a page **biasing** a decision, not escaping the schema. Keep the adversarial
fixture and assert results are unchanged.

## Acceptance criteria
- Every state fits the token budget with headroom — asserted for the largest fixture, across all three scopes.
- **Truncation never occurs on the fixture corpus.** If it would, the budgeter splits deterministically and discloses it.
- Section-scope states contain no content from other sections — assert this; it is what makes the self-containment question meaningful.
- Concurrency is bounded and configurable; a test asserts the ceiling is respected.
- Low-confidence answers become `cannot_assess`, threshold asserted.
- Adversarial injection fixture yields results identical to the clean page.
- Provider disabled → complete, clearly-labelled static-only result.

## Handoff notes
**Built.** Scope-partitioned state (page / section / passage), versioned question
catalogue, bounded concurrency, confidence gate.

- **Chunking was rejected in favour of scoping.** Measured: whole-page state 13,050 tokens versus largest scoped state **293**. Truncation never occurs, and it is more correct — self-containment is a question about the section alone.
- Section states contain no other section's text; asserted by test.
- **Supersedes the original "one call per page" rule.** That optimised call count at the expense of correctness. A page is ~30 calls at concurrency 14.
- Measured: a direct Jev call is 876 ms for 1 question and 941 ms for 4. **Questions are nearly free; calls are what cost.** The remaining optimisation is batching sections (~30 → ~6), which would weaken the self-containment question.
