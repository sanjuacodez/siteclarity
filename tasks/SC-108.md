## Purpose
One interface for typed decisions, with swappable backends. SiteClarity is a practical
System One application: this adapter is the point where that is made real and portable.

## Background
System One models evaluate a **state** against **typed questions** and return decisions —
never text. Three primitives: **Choice** (option from a list → `choice`, `probabilities`,
`confidence`), **Score** (rubric → `score`, `probabilities`, `confidence`), **Noul** (is this
statement true → 0–1). All questions are evaluated **in parallel, in isolation, against the
same state, in one request**. There is no memory; state is supplied per call.

## Scope — in
- Interface:
  ```ts
  type Question = ChoiceQ | ScoreQ | NoulQ
  type Answer   = { confidence: number; probabilities?: Record<string, number>; ... }
  decide(state: State, questions: Question[]): Promise<Answer[]>
  ```
- **Backends:**
  | Backend | How | Notes |
  | --- | --- | --- |
  | **Workers AI** (default) | `env.AI.run('typesafe/jev', …)` | No API key; free allowance |
  | **System One HTTP** | `POST /v1/systemone` | Covers **Jev API, Kev, Decider** — base-URL swap only |
  | **Laya** | own interface | Apache-2.0, local GPU; thin translation layer |
  | **Replay** | fixtures | **Default in tests**; record mode behind an explicit flag |
- Zod validation of every response. Malformed or missing answer → `cannot_assess`, never a fabricated value.
- Usage accounting surfaced in `AnalysisResult.provider`.
- Graceful degradation: backend unavailable or over quota → typed result that SC-109 renders as static-only. Not an exception.

## Scope — out
No question authoring and no state construction — that is SC-109. This task is transport,
validation, portability and degradation only.

## Acceptance criteria
- Full suite passes in replay mode: offline, no key, no cost.
- Switching Workers AI → Jev API → Kev → Decider is **configuration only**, no call-site change. Prove it with a test that runs the same questions through two backends against recorded fixtures.
- Laya's differing interface is isolated behind the adapter; nothing upstream knows.
- No model ID or base URL hardcoded in source.
- A malformed backend response degrades to `cannot_assess` and is logged, never propagated.

## Handoff notes
**Built.** `DecisionBackend` interface with `workersai`, `systemone` and `replay`.

- **Two wire-shape facts only a live call revealed, both of which would have shipped broken:**
  1. `noul` answers carry **no `confidence` field**. The value is the signal (0.96 confident yes, 0.5 maximal uncertainty). Confidence is derived as `|value − 0.5| × 2`. The schema originally required `confidence` and would have rejected every yes/no answer — the majority of the catalogue.
  2. `score` is a **0-based probability-weighted index** over the rubric, not a rating. `0.48` across five levels sits between level 0 and level 1. It is not "48%".
- Jev, Kev and Decider share `POST /v1/systemone`; switching is a base-URL change.
- **Unmeasured:** neuron cost per Jev call on the Workers AI binding, and whether `AI` binding calls count against the 50-external or 1,000-CF-services subrequest limit. All live testing used the `systemone` backend with an API key.
