## Purpose
Define the shape every module — all ten, eventually — uses to express a finding. This task
exists early **specifically** so that module 6 can aggregate nine modules later without
forcing a rewrite of any of them.

## Scope — in
Zod schemas plus inferred types for:
- `Finding` — `id`, `module`, `observation`, `evidence[]`, `whyItMatters`, `recommendedAction`, `affects[]`, `priority`, `confidence`.
- `Decision` — a System One answer: `{ kind: 'choice'|'score'|'noul', value, probabilities?, confidence }`. `confidence` is the model's **calibrated** figure, not a self-report, and drives `cannot_assess`.
- `Question` — `ChoiceQ | ScoreQ | NoulQ`, the typed question shapes sent to the decision model.
- `EvidenceRef` — `{ passageId, quote }`. `quote` is **populated by code from the passage store**, never by a model.
- `CoverageLabel` — `answered | partial | conflicting | not_found_in_scope | cannot_assess`.
- `Applicability` — a **separate field** from the label; a question can be inapplicable yet unanswered.
- `AnalysisResult` — `{ schemaVersion, input, limits, sections[], findings[], provider, timings }`.
- `Limits` — what was examined, what was not, and why. Never optional. Never empty.
- `ModuleId` — enumerates all ten modules now, even though only one is implemented.

## Scope — out
No logic that produces findings. Schemas and types only.

## Files owned
`src/contracts/**`

## Acceptance criteria
- `schemaVersion` present and asserted in tests.
- A `Finding` whose `evidence[].quote` is absent or empty fails validation.
- `AnalysisResult` without a populated `limits` block fails validation.
- No field permits a numeric overall score (invariant 2) — assert this in a test so a future agent cannot quietly add one. Note: a per-question Jev `Score` is a **rubric answer**, not a page grade; the schema must make that distinction unambiguous so the two are never conflated.
- `Finding.observation`, `whyItMatters` and `recommendedAction` are **template-rendered**, never model-authored. The type should make that provenance explicit.
- Round-trip test: parse → serialise → parse yields a deep-equal object.

## Validation
```
npm test -- contracts
```

## Change policy
Additive fields: allowed with a `schemaVersion` bump. Renames and removals: follow
`AGENTS.md` §5 — stop, write it up, ask.

`CoverageLabel`, `Applicability`, all Zod.

- Added since planning: `highlights` (words to mark in the quote) and `copySource` (provenance of the copy; `'template'` only).
