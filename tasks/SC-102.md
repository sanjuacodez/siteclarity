## Purpose
A running Worker with routing, validated configuration, typed bindings, structured logging,
and a single error envelope — so every later task plugs into a known shape.

## Scope — in
- Hono app; routes `GET /health` and `POST /api/analyze` (the latter returning `501 Not Implemented` for now).
- `wrangler.jsonc` with the `AI` binding and an **optional** KV namespace (share links, off by default).
- Config module: environment parsed and validated with Zod at startup; unknown/missing values fail loudly with a clear message.
- One error envelope used everywhere: `{ error: { code, message, details? } }`.
- Logger (no bare `console.log` anywhere in the codebase after this task).

## Scope — out
No URL handling (SC-103). No extraction (SC-104). No provider calls (SC-108). `/api/analyze`
stays a stub.

## Files owned
`src/index.ts`, `src/routes/**`, `src/lib/config.ts`, `src/lib/logger.ts`,
`src/lib/errors.ts`, `wrangler.jsonc`

## Contracts produced
- `AppEnv` — typed bindings, consumed by every later task.
- Error envelope shape — consumed by SC-112.

## Acceptance criteria
- `wrangler dev` starts; `GET /health` returns 200 with version and build info.
- Missing or malformed config produces a clear startup error, never a silent default.
- KV binding is genuinely optional: the Worker runs correctly with no KV namespace bound.
- Handlers are CPU-trivial (this is the baseline SC-114 measures against).

## Validation
```
npx wrangler dev &
curl -s localhost:8787/health | jq .
curl -s -X POST localhost:8787/api/analyze -d '{}' -i | head -1   # expect 501
npm test
```
